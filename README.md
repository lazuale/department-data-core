# department-data-core

**Department Data Core (DDC)** — каноны проектирования реляционной модели данных на PostgreSQL. Они задают правила определения фактов, ключей, связей, ограничений и границ ответственности.

DDC — не готовый продукт и не шаблон таблиц. Модель каждого источника выводится из его предметного смысла и проверяемых данных. Старые реализации не считаются доказательством правильности решений.

## С чего начать

1. [Моделирование данных](docs/data-modeling-standard.md) — как установить смысл строк, ключи и связи.
2. [Практический пример](docs/practical-modeling-example.md) — диагностические запросы, ложная декомпозиция, проверка ключей и опыт T1/T2.
3. [Архитектура базы данных](docs/data-core-architecture-standard.md) — куда относятся данные и как разграничить доступ.
4. [Именование SQL-объектов](docs/naming-convention.md) — правила имён в PostgreSQL.

Пример учебный: он показывает метод проверки, а не готовую модель реального источника.
