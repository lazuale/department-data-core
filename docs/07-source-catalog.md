# Карта источников и кандидатов на интеграцию

Это **предварительная карта**, собранная по описанным рабочим процессам. Перечисленные наборы не считаются загруженными в DDC, если это не подтверждено эксплуатационной проверкой. Названия внешних систем и сведения об их настройке, пользователях и инфраструктуре здесь сознательно не публикуются.

## Система-источник и набор данных — разные уровни

Одна учётная система может передавать несколько самостоятельных наборов. Для DDC это один поставщик, но разные контракты данных, правила обновления, зернистость и связи.

| Группа источника | Набор данных | Потенциальные общие объекты | Что требуется уточнить |
| --- | --- | --- | --- |
| 1С | Путевые листы | ТС, водитель, организация, участок, дата/смена, работа | Идентификаторы, строки работ и топлива, правила повторных снимков |
| 1С | Табели | Сотрудник, подразделение, период | Зернистость, виды времени, исправления, первичный ключ |
| 1С | ТТН | ТС, работа, перевозка, контрагент, дата | Документ, рейс, поездка и строка перевозки — разные уровни; подтвердить кратность |
| 1С | Отдельные документы заправки | ТС, топливо, дата, операция выдачи | Как сопоставляются с заправкой в ПЛ; исключить двойной учёт |
| 1С | Ремонтные листы | ТС, ремонт, заявка, простой, период | Состояния, состав работ, единица ремонта, связь с простоями |
| 1С | Прочие документы | Зависит от документа | Дополнять после инвентаризации, не создавать заранее |
| Внешняя система регистрации прохождений | События прохождения сотрудников | Человек, момент, точка прохода (если есть в данных) | Идентичность человека, точность и смысл события, часы, доступ |
| Внешняя система табельного учёта | Табельные сведения | Человек, период, участок (если есть в данных) | Строка и период табеля, статусы корректировок, совпадение с 1С |
| Провайдеры топливных карт | Операции по картам | Карта, операция, топливо, дата/время, возможно ТС и организация | Идентификатор транзакции, возвраты/отмены, единицы измерения, назначение карты на ТС и период |
| Системы мониторинга ТС | Выгрузки телематики; фактический состав неизвестен | Устройство, ТС, момент/интервал, возможные пробег, движение, моточасы, топливо | Какие показатели действительно доступны, идентификатор устройства, часовой пояс, качество измерений, интервалы и разрывы данных |

Приоритетные фактические источники определены; доступные форматы, состав колонок и ключи отдельных наборов **ещё не подтверждены** этой картой.

## Основные интеграционные контуры

### Транспорт и производственная работа

```text
                  1С / путевые листы
                           |
                       Транспорт
                 /     /   \       \
          1С / ТТН  1С /    Карты   Мониторинг
                   заправки  ГСМ
                           |
                      1С / ремонты
```

Центральный кандидат — идентичность ТС. Но карта может быть закреплена за машиной лишь на некоторый период, а мониторинговое устройство может быть перенесено. Поэтому нужны подтверждённые соответствия «карта ↔ ТС» и «устройство ↔ ТС» с учётом дат, а не однократное соединение по текущему ГРЗ.

Идентичность документа, операции, рейса и смены устанавливается отдельно; связи могут быть один-ко-многим и многие-ко-многим. Сходство даты, госномера и участка недостаточно для автоматического отождествления двух операций.

### Топливо и телематика: отдельные факты

**Документ заправки 1С**, **заправка внутри путевого листа**, **транзакция топливной карты** и **изменение уровня топлива по датчику** (если такие измерения есть) — не четыре подтверждения одной операции автоматически. У них разные авторы, время регистрации, корректировки и зернистость. Нужно различать совпадение, отсутствие пары, частичное соответствие, отмену транзакции и неоднозначность.

**Пробег и наработка** из путевого листа и из мониторинга также не обязаны совпадать: источники могут использовать разные датчики, временные границы, единицы и алгоритмы. Контрольные показатели допустимы только после определения их смысла, временного интервала и допустимого расхождения.

### Персонал, время и прохождения

```text
           1С / табель
                |
             Сотрудник
              /    \
   Внешний табель  События прохождения
```

Нужна предметная идентичность работника между системами. Данные табеля — учёт рабочего времени, события прохождения — регистрация события доступа. Их нельзя подменять друг другом без отдельных правил рабочего процесса. Понятие смены может требовать начала, окончания и перехода через полночь.

### Потенциальный мост между контурами

Водитель в путевом листе может быть связан с сотрудником из табеля. Эту связь допустимо использовать только при установленном соответствии идентификаторов; ФИО и одна дата сами по себе не гарантируют совпадения.

## Как делать интеграцию без потери смысла

1. Для каждого набора отдельно описать источник, структуру записи, область уникальности ключа, полноту и порядок исправлений.
2. Проверить, что является **одним** событием / документом / строкой / периодом.
3. Определить предметные объекты, которые действительно общие для двух наборов.
4. Выявить надёжные внешние идентификаторы и при необходимости использовать `xref`.
5. Разобрать неоднозначные и несовпадающие записи, не скрывая их через `DISTINCT` или случайный выбор.
6. Строить `mart` с учётом кратности: например, не дублировать литры топлива после соединения с несколькими строками перевозок.

## Что должно быть проверено первым

**Транспортный контур:** наличие устойчивой связи ТС между путевыми, ТТН, заправками, ремонтами, операциями по топливным картам и устройствами мониторинга. Затем — правила сопоставления отдельных операций и интервалов по предметным контрактам.

**Контур персонала:** идентичность работника между табелями и системой прохождений; затем определения смены, отработанного времени, корректировок и расхождений.

**Мост:** связь водителя из путевого листа с человеком в кадрово-табельных данных. Отсутствие подтверждённой связи явно показывается, а не угадывается.

Сначала обследуется реальный состав выгрузок. Не нужно заранее создавать универсальную таблицу «все события» или единый неразличимый справочник документов.
