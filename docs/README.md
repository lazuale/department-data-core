# Канон базы данных DDC

[Главная](../README.md)

Канон разделён на три части. Архитектура описывает размещение данных и границы ответственности. Моделирование определяет смысл данных и инварианты. SQL naming посвящён только именам объектов PostgreSQL.

Порядок чтения: [Архитектура](data-core-architecture-standard.md) → [Моделирование](data-modeling-standard.md) → [SQL naming](naming-convention.md).

| Документ | Что в нём искать | Разделы |
|---|---|---|
| [Архитектура базы данных](data-core-architecture-standard.md) | граница БД, обзор схем, входные данные, происхождение и SQL-интерфейсы | A01–A05 |
| [Моделирование данных](data-modeling-standard.md) | зернистость, идентичность, ключи, отношения, значения и целостность | M01–M09 |
| [SQL naming](naming-convention.md) | форма SQL-имени, его смысл и квалификация ссылок | N01–N03 |

Обзорная диаграмма и таблица схем находятся в [A03](data-core-architecture-standard.md#a03-схемы-и-зависимости). Основные понятия модели введены в [M01](data-modeling-standard.md#m01-модель-и-зернистость); пример простой ссылки и самостоятельного отношения — в [M03](data-modeling-standard.md#m03-отношения-и-структура-атрибутов).

Значения нормативных слов определены в начале [архитектуры базы данных](data-core-architecture-standard.md#сила-нормативных-утверждений).
