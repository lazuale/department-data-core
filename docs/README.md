# Документация

[← Главная](../README.md)

Документы описывают архитектуру v1 единого ядра данных. Читать их лучше в указанном порядке: каждый следующий документ опирается на границы, зафиксированные выше.

| Порядок | Документ | Назначение |
|---:|---|---|
| 1 | [Видение и границы](vision-and-scope.md) | зачем существует проект и что входит в его область |
| 2 | [Архитектура ядра](data-core-architecture-standard.md) | схемы PostgreSQL и границы ответственности |
| 3 | [Моделирование данных](data-modeling-standard.md) | сущности, факты, ключи, связи и история |
| 4 | [Именование](naming-convention.md) | единые правила именования SQL-объектов, технических идентификаторов и файлов |
| 5 | [Подключение новых наборов данных](registry-integration-standard.md) | единый порядок интеграции нового источника |
| 6 | [Клиентский API](client-api-standard.md) | граница рабочих приложений и серверной логики |
| 7 | [Аналитическая модель](analytics-standard.md) | `mart`, факты, измерения и перекрестный анализ |
| 8 | [Требования к рабочей среде](production-baseline.md) | минимальные требования к эксплуатации |

## По задаче

| Задача | Документы |
|---|---|
| Быстро понять идею | [Видение и границы](vision-and-scope.md) → [Архитектура ядра](data-core-architecture-standard.md) |
| Спроектировать новую предметную область | [Моделирование данных](data-modeling-standard.md) → [Именование](naming-convention.md) |
| Подключить Excel, CSV, API или другую систему | [Подключение новых наборов данных](registry-integration-standard.md) |
| Назвать SQL-объект или техническое поле | [Именование](naming-convention.md) |
| Сделать рабочий клиент | [Клиентский API](client-api-standard.md) |
| Построить отчетность и перекрестную аналитику | [Аналитическая модель](analytics-standard.md) |
| Развернуть и сопровождать базу | [Требования к рабочей среде](production-baseline.md) |

Этот файл служит только навигацией. Нормативные правила находятся в соответствующих стандартах.
